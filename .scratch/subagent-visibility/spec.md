# 看板顯示派出去的子代理

## Problem Statement

主代理派出子代理之後，我想從 **監看視窗** 看出這個 **Session** 是不是還在進行中、是不是正在等子代理回傳。現在做不到：**前景 Subagent** 在主代理等它的整段時間，卡片底下完全沒有 `↳` 子卡片，看起來就像主代理什麼都沒在等。

實測（真的 `claude`，停用背景任務逼出前景子代理，run `r1117-162214-ceeb`）：

- 主代理呼叫 Agent 後約 9 秒，狀態回報的 `tasks` 一直是空的；要等到子代理**自己的某個 Bash 呼叫結束**，才被登記成 `running`。子代理只用 Read、Grep 時，整段都不會出現。
- 原因：子代理清單只在 `tool.call` 的 `next(e)` 回來之後才刷新（`register.tsx` 的 `tool.call` hook）。前景子代理的 `next(e)` 要等它跑完才回來。
- 另外，子代理自己的工具呼叫也會觸發 `tool.call`，把整個 **Session** 的「最近活動」改成子代理的動作（例如 `$ find …`），看起來像主代理在跑那個指令。

背景 Subagent 沒有這個問題：`next(e)` 很快回來，所以刷新得到。

## Solution

讓看板能即時、正確地回答「主代理在不在等子代理」：

- 子代理一啟動就登記，不等工具呼叫結束；前景、背景都一樣。
- 區分 **前景 Subagent** 與 **背景 Subagent**，前景的標示「主代理在等它」。
- 失敗的子代理留一行 `↳ ! 描述`，直到下個回合開始，使用者才知道是哪一個出了事。
- **最近活動** 只反映主代理自己的動作；主代理停在前景子代理上時顯示「等待子代理 n 個」。

名詞定義見 `GLOSSARY.md` 的 **Subagent**、**前景 Subagent**、**背景 Subagent**、**等待子代理**。

## User Stories

1. 身為 switchboard 使用者，我想在主代理派出前景子代理的那一刻，就在卡片底下看到它，這樣我知道主代理不是卡住。
2. 身為 switchboard 使用者，我想分辨哪些子代理是主代理正在等的（前景）、哪些不擋主代理（背景），這樣我能判斷主代理是否還要等。
3. 身為 switchboard 使用者，我想在主代理等前景子代理時，看到最近活動是「等待子代理 n 個」，這樣不會以為主代理在跑子代理內部的指令。
4. 身為 switchboard 使用者，我想讓子代理的內部工具呼叫不要改掉主代理的最近活動，這樣看板反映的是主代理本身。
5. 身為 switchboard 使用者，我想在子代理失敗時留下一行 `↳ ! 描述`，直到下個回合開始，這樣我知道是哪一個失敗、為什麼主代理停住。
6. 身為 switchboard 使用者，我想讓正常完成的子代理立刻消失，這樣子卡片區不會堆滿已經沒用的資訊。
7. 身為 switchboard 使用者，我想看到等待中（子代理自己在等背景工作或核准）的子代理用 `⏸︎` 標示，這樣能分辨它是在跑還是在等。
8. 身為同時派出很多子代理的使用者，我想讓子卡片依「前景執行中 → 失敗 → 等待中 → 背景執行中」排序，這樣最影響主代理的排最前面。
9. 身為同時派出很多子代理的使用者，我想讓卡片最多顯示 3 行、其餘收成 `+n 個`，這樣卡片不會被撐爆。
10. 身為想看全部子代理的使用者，我想展開卡片明細時看到完整清單，這樣不被 3 行限制擋住。
11. 身為主代理回合已結束、背景子代理還在跑的使用者，我想讓這個 Session 仍算 **工作中**，這樣我不會誤以為它閒置（現有行為，不能退化）。
12. 身為使用舊版回報檔的使用者，我想讓沒有前景／背景欄位的舊回報照舊顯示，這樣升級不會壞掉。
13. 身為非中文使用者，我想讓新文字（等待子代理、前景標示、失敗標示）依我選的語言顯示五種語言。
14. 身為讀螢幕閱讀器的使用者，我想讓前景、失敗的標示不只靠符號，這樣看不到符號也知道狀態。

## Implementation Decisions

- **分辨前景／背景**：用 `agent.spawn` 事件的 `background: boolean`（型別檔：true 代表背景或遠端；停用背景任務時引擎強制為 false）。在 `agent.spawn` 的 `next(e)` 回來後，以 `agentId` 為鍵記下前景／背景。`Task`（`types/index.d.ts`）加可省略的 `mode: 'foreground' | 'background'`；舊回報沒有這個欄位，視為背景（沿用現有顯示）。
- **刷新時機**：除了現有的 `tool.call` 之後，加上 `agent.spawn`（啟動時）和子代理自己的 `turn.complete`（`e.agentId` 有值）。第一張 ticket 先實測 `agent.spawn` 的 `next(e)` 對前景子代理是啟動時還是跑完才回來；若是跑完才回來，改在進入 `agent.spawn` hook 時就登記，不等 `next(e)`。
- **狀態對應**：`taskStatusOf` 補 `idle`（等訊息的 teammate）：不算 `done`，算 `waiting`。其餘沿用。
- **子卡片列**（`register.tsx` 的 `subtasksOf` 與渲染）：
  - 顯示：`running`（前景、背景）、`waiting`、`failed`；正常完成不顯示。
  - 排序：前景執行中 → 失敗 → 等待中 → 背景執行中；同組維持原順序。
  - 標示：前景 `↳ ⏳ 描述`，失敗 `↳ ! 描述`，等待 `↳ ⏸︎ 描述`，背景維持 `↳ 描述`。符號放進 `GLYPHS` 表，和既有符號一起登記。
  - 上限 3 行，其餘 `+n 個`；展開明細時完整列出（現在最多 5 個，放寬）。
  - 失敗的子代理留到下個回合開始（`turn.start` 且 `agentId` 為空）才清掉。
- **標題列計數**：現有 `⏸︎n`、`!n` 計數維持；執行中已逐列列出時不重複 `↻`（現有行為）。
- **最近活動**：
  - `tool.call` hook 在 `e.agentId !== undefined`（子代理自己的呼叫）時不寫 `activity`。
  - 有前景 Subagent 執行中時，`activity` 寫成語言中立的標記（例如 `{ waitingOnSubagents: n }`），由監看視窗依語言顯示「等待子代理 n 個」；沒有前景時沿用主代理最近一次呼叫的摘要。
- **不新增 Session 狀態**：**等待子代理** 仍屬 **工作中**，**Session 狀態** 那組互斥定義不動。
- **多國語言**：新文字加進 `i18n.ts` 五種語言。
- **文件**：`GLOSSARY.md` 已更新；README 與使用說明（`docs/guide/usage.*`）五種語言補一段子代理在卡片上怎麼看。合併的 PR 跳 minor。

## Testing Decisions

- 只有一個 seam：`tests/world.ts` 的整合測試世界。從使用者看得到的結果驗收：子卡片的文字與順序、最近活動欄位、狀態回報裡的 `tasks`。不測內部函式。
- world 要補：假的 `agent.list()`（可設定每個子代理的 `status`、`type`、`name`）、可觸發 `agent.spawn`（帶 `background`）與子代理自己的 `tool.call`、`turn.complete`。
- 要涵蓋的情境：前景派出的當下就列出（不等工具結束）；前景與背景並存的排序與標示；失敗留到下個回合；等待中標示；正常完成消失；超過 3 個收成 `+n`、展開後全列；子代理的 `tool.call` 不改主代理最近活動；等前景子代理時顯示「等待子代理 n 個」；舊回報（沒有 `mode`）照舊；五種語言。
- 前例：`background-task-subcards.test.ts`（子卡片、`+n`、回合結束後仍有子卡片）、`background-tasks-busy.test.ts`（背景任務讓 Session 算工作中）、`ux-12-i18n-metadata.test.ts`（多國語言）。
- **真實引擎驗證**（`verify-switchboard`）：單元測試是自己模擬的事件順序，驗不出引擎的真實行為。需要在真的 `claude` 裡派前景子代理（啟動 session 時帶 `CLAUDE_CODE_DISABLE_BACKGROUND_TASKS=1`，否則這版引擎會自動丟到背景），記錄狀態回報在整段等待期間的 `tasks` 與 `activity`。上一輪實測的做法與證據見 Further Notes。

## Out of Scope

- 巢狀子代理的層級縮排（`parentId` 目前不用）；平鋪顯示即可。
- 子代理的執行時間、token 用量、完整輸出。
- 從看板跳進子代理的對話或中止子代理。
- 新增 **Session 狀態** 或改動 **待處理** 的判斷。
- 子代理需要核准時的 **待核准** 判斷（沿用現有行為，不在此範圍）。
- 雲端 Session。
