狀態模型原型：Session 狀態怎麼判定

要回答的問題：每個 Session 用自己的 hook 寫出狀態回報，清單再把它和 Claude Code 的系統紀錄合併。 規則是：pid 死了就移除；兩邊不一致時，以時間較新的為準；狀態回報裡的細節，只在它的狀態和最終判定一致時才顯示； 只有在「轉進」需要你處理的那一刻才通知。這套規則在真實的事件順序下，會不會判錯、漏通知或重複通知？
