# switchboard UI 評審：三位設計師的共識

三位設計師：A（資訊架構與互動流程）、B（視覺與卡片）、C（設計系統、無障礙、多語系）。
進行了三輪：獨立評審（A 13 條、B 15 條、C 15 條）→ 逐條互評與合併 → 共識投票（39 條，三人全數接受）。
本文件只收三人都接受的內容。各輪原稿在同一資料夾的 round1-*.md、round2-*.md、round3-*.md。

## 應保留的做法
- 三層外框表達重要程度；情境行一張卡只放一件事；標題有寬度預算。
- 依狀態分區、需要你處理排最前、等最久的排最上面。
- ▸／▾ 作為一致的揭露符號。

---

## 一、畫面設計

1. **示意圖與程式同步（高）**：assets/board/board.*.png 已過時（右上角還是「檢視／View」、寫 `ctx`、帳號卡位置不對、沒有來源符號、有程式沒有的淡橘底色）。render.mjs 的 Desktop 版和終端機版改用同一份樣本、版面順序與 i18n 字串，重新產生 10 張圖。等其他條目定案後再產生。第二步補一張「狀態總覽」圖，涵蓋出錯中止、狀態不明、展開明細、看不到狀態、沒有在等你。PR 檢查清單加一條：「動到 i18n.ts、LOOK、GLYPHS 或卡片版面時，要重新產生 assets/board」。
2. **分組間距**：每個分區（分區標題＋卡片）各包一層 `Box flexDirection="column" rowGap="xs"`，根節點 `rowGap="md"`，閒置列之間 0。在終端機上，組內 0 行、組間 1 行。間距一律用 step 名稱，不寫數字。
3. **頁首的三種形態**：
   - 有 Session 在等你：拿掉外框，改成不加框的分區標題。第一行 `▲ 2 個需要你處理`（warning bold，Desktop 用 `heading`），第二行 caption `核准 1 · 回答 1 · 最長 3m`，拿掉「點選標題前往」。
   - 沒有在等你：一行不加框的 `✓ 沒有 Session 需要你處理`，不再重複各分區數量；只有 0 筆 Session 時才補「沒有其他執行中的 Session」。
   - 看不到狀態：保留有框的警示卡，外框改 `double` + warning。Desktop 不支援 double 時退回 `round` + warning，加 ⚠ 標題；紅色保留給出錯中止。說明文字用預設色，只有引擎回傳的原始錯誤訊息用 error。錯誤分成「結論」和「路徑（truncate-middle）」兩行。不放「重新掃描」（本來每 3 秒就自動重試），改成一行 dim 的「每 3 秒自動重試」，再加一個指向對應語言 README 錨點的「疑難排解」`Link`。
4. **粗琥珀框專屬需要你處理的 Session 卡片**，紅色粗框專屬出錯中止的卡片。
5. **分區標題的 glyph**：需要你處理的標題以 ▲ 開頭。工作中、閒置的標題先不加 glyph，等實機截圖確認 CJK 在 iTerm／Terminal.app 是否畫不出粗體，再決定。
6. **帳號用量卡片**：平常用 `borderDimColor`，退成頁尾；達到門檻提到頂端時才加強外框。5h／週兩個標籤用 `displayWidth` 補到同寬，只取目前語言；整行用 `Text mono tabular`，讓用量條起點對齊。
7. **重排時點錯**：焦點在監看視窗裡時只凍結順序。已經離開需要你處理的卡片原地更新內容和外框樣式，並拿掉「前往處理」，凍結結束後才移位。⚠ GLOSSARY 把這件事列為「之後再考慮」，要先在 Flagged ambiguities 改寫決議。決議文字寫「焦點」，不寫「游標」，因為 mod API 沒有 hover 事件。
8. 閒置收合時補「最近：…」：這次不做。

## 二、選單設計

1. **設定面板**：
   - 位置：移到頁首下方、卡片上方。
   - 分成「卡片內容」（在前）和「一般」兩區，不加子框。區塊標題直接標出範圍：`卡片內容 · 工作中`。
   - 欄位清單只列該分區有效的欄位，例如「進度」「目前動作」只在工作中，「最後回覆」只在閒置；`densityOf` 也只比對有效欄位。
   - 分區選擇存進 store、記住上次的選擇，第一次打開預設「需要你處理」。
   - 語言、計費在 Desktop 改用 `Select`；終端機先實機確認 Select 展開後的高度，太高就維持按鈕列。
   - ☑/☐ 開關傳含狀態的 `label`；語言選項用母語名稱（en 寫 English）。
   - 底部加「完成」按鈕，不加 ▴。
2. **打開按鈕與等你計數**：▲n 是等你計數唯一的寫法。
   - 有計數時，按鈕寫成 `▲2 需要你處理 · ▦ 打開`，▲2 用 warning bold；沒有計數時是 `▦ 打開監看視窗`。
   - Pane 標題寫成 `Switchboard · ▲2`。
   - 按鈕的 `label` 寫成「打開監看視窗，2 個需要你處理」。
   - ⚠ 要同步更新 ADR-0006 和 GLOSSARY 的例句（決策本身不變）。
3. **焦點即跳轉**：現在用 Tab 經過卡片標題就會跳轉，違反 WCAG 3.2.1。改法：記下這個 Pane 上一次 `ui.focus` 的時間，間隔少於 10 秒視為 Tab 瀏覽，不跳轉；超過 10 秒或第一次取得焦點才跳轉；Enter 或按下一律跳轉。README 的鍵盤表要同步更新，寫明這個例外，並提示使用數字快捷鍵。
4. **數字快捷鍵**：需要你處理卡片的「前往處理」依排序帶 `hotkey="1"`…`"9"`，按鈕上顯示 dim 的數字（`1 前往處理 →`）。⚠ 數字會跟著排序變動，必須和第一節第 7 點的凍結重排一起上線。
5. **閒置分區**：標題整列做成 `Button plain`，揭露箭頭放在文字後面（`閒置 3 ▾`），和「設定 ▸」一致。
6. **自動打開的 toast**：寫出完整的操作路徑。「不再自動打開」按鈕只在這個 Session 剛被手動關掉、而且自動打開開著時出現，下一次打開或回合結束後就消失。

## 三、卡片設計

1. **一個主要動作**：需要你處理卡片只有一顆「前往處理 →」，放在中繼資料帶同一列的右端（`row` + `space-between` + `flexWrap`），寬度不夠才換列。全部用 secondary，不給第一張 primary，由數字 1 標出先後。標題仍可點作為捷徑，但不再教。
2. **時間與展開分開**：時間獨立成 `Text caption dimColor tabular`，不可點；展開鈕只畫 ▸／▾，並傳 `label`（「顯示明細：{標題}」）。
3. **來源符號**：從「狀態標籤和標題之間」移到標題列右側群組、時間前面，用 dimColor。所有密度都顯示，全部同一種來源時也不省略。這樣就不會讀成「核准 → 標題」。空間不夠時，依序拿掉徽章、拿掉來源符號，最後把「目前」換成 ✦。
4. **✎ 只代表 VS Code**：Edit／Write／MultiEdit／NotebookEdit 的情境行改寫成 `Edit 檔名`，和 `Read 檔名` 一致。
5. **中繼資料帶**：
   - 卡片上用短標籤（`ctx`），完整名稱只出現在設定面板和展開明細。
   - 分段之間用 `columnGap="md"`，不另插 ·。
   - 位置和分支那段改用 `color="subtle"`，要在兩個主題下確認對比；Context 低於 80% 維持 dim。
   - 數字為 0 的那一邊不畫（不再出現紅色 −0）；展開明細不再重複 Context 和分支。
6. **PR 欄位不只靠顏色**：開啟寫 `#12 ↗`；已合併寫 `#12 ↗ 已合併`（merged 色）；已關閉的 `#12` 加刪除線、用 inactive。不用 ✓，因為它已經代表「完成」。
7. **沒有 PR**：「前往建立 PR →」改成不可點的 dim 文字「無 PR」（No PR／无 PR／PR なし／PR 없음），只在有工作時顯示。
8. **工作中的顏色**：卡片上的 ◉ 從 `claude` 橘改成 `text`，讓卡片上「橘色＝需要你處理」沒有例外；`claude` 色只留在工作中分區標題這一處。實作後在淺色與深色主題截圖確認。
9. **閒置列對齊**：`paddingX={isTerminal ? 2 : 1}`，終端機寬度用 cardWidth。Desktop 量起來本來就對齊。
10. **狀態標籤**拆成「glyph Text＋標籤 Text」，字串不帶空格，`.replace('▲ ', '✕ ')` 這種寫法一併拿掉。

## 四、設計系統

1. **字級四級**：heading＝等你計數；body semibold＝卡片標題；footnote＝分區標題、情境行；caption＝中繼資料。
2. **顏色規則**（寫進文件）：warning 色的大面積元素只用在需要注意的狀態；每種狀態和其他狀態至少在 glyph、外框、文字標籤三者中的兩項不同，顏色只是輔助。
3. **GLYPHS 總表**：在 board.ts 建表，每個 glyph 註明意思、碼位、EA 寬度，README 圖例由它產生。加一個測試，檢查「一符一義、一義一符」，以及新增的字不是 EA=W。⟳ 改成 ↻，⏸ 加 VS15。箭頭語彙固定為：→ 跳轉、↗ 外部連結、▸／▾ 揭露（放在文字後面）。
4. **Ambiguous 寬度（低）**：終端機不分語言，標題列的寬度預算加上 Ambiguous 字元的數量作為餘裕；之後新增的 glyph 一律選非 Ambiguous 的字。
5. **無障礙**：只有符號的控件（展開鈕、PR、閒置收合、✦、打開按鈕）一律傳 `label`，畫面不變。
6. **多語系**：
   - CJK 不用斜體，由各語言的 Messages 決定。
   - 標點：zh-CN 改用 “”，`?` 用半形後面接一格空白，zh-TW 統一 ＋ 的寫法。
   - 時間單位統一，不再混用 `3m` 和「12 秒前」、`5h` 和「5時間」；時間和百分比加 `tabular`。
   - ko、ja 的「閒置」不能改成任何意思是「等待」的詞（C 撤回了「대기 중」）；現有的 ko 유휴、ja 待機中，請母語者確認不會讀成「在等你」。

## 需要你拍板或實機確認的事
- **要你拍板**：
  - ADR-0006 和 GLOSSARY 的例句改寫（打開按鈕的字序）。
  - GLOSSARY 中「重排凍結」的決議改寫。
- **要實機確認**：
  - Desktop 能不能畫 `borderStyle="double"`。
  - CJK 在真實終端機能不能畫粗體（目前的證據只來自示意圖用的字型）。
  - 終端機 Select 展開後的高度。
  - `claude` 橘與 warning 在兩個主題下的觀感。
  - `subtle` 色的對比。
- **注意**：mod API 的元件型別不在 repo 裡（types/index.d.ts 只有 mod 自己的型別），可行性是對照 plugin-authoring skill 附的 claude-code.d.ts 確認的。
