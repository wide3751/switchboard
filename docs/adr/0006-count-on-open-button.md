# 打開按鈕上顯示等你計數

> 修訂 [0003](0003-single-desktop-board.md) 的「只有監看視窗所在的 Session 會 polling 所有 Session 的資料」。

監看視窗沒打開時，輸入框上方的「▦ 打開監看視窗」按鈕也顯示等你計數，例如 `▦ 打開監看視窗 · ▲2`；沒有 Session 在等時只顯示按鈕本身。為此每個沒開監看視窗的 Session 每 15 秒做一次輕量掃描：只讀 Session 紀錄、狀態回報，跑一次 `ps`，不跑 git、gh，也不算卡片的其他欄位。[0005](0005-no-own-needs-you-alert.md) 決定 switchboard 不發通知之後，監看視窗沒開時 switchboard 本身沒有任何訊號，而 CLI 預設不自動打開監看視窗；[0004](0004-cli-board.md) 已經接受了每個 CLI Session 輸入框上方多一行的成本，讓這一行帶上計數，它才有資訊量。

## Considered Options

- **只在自己的事件（回合開始、結束）更新計數，不掃描**：沒有背景工作，但數字常常是舊的。舊的 0 會讓使用者以為沒事，比沒有計數更糟。
- **不顯示計數**：維持 0003 的「不掃描」，但監看視窗沒開時使用者什麼都不知道。
- **和監看視窗一樣每 3 秒掃描**：比較即時，但每個 Session 都這樣做，成本隨 Session 數量放大；按鈕只需要知道「有沒有、有幾個」，15 秒內的延遲可以接受。

## Consequences

- 每個 Session 都有背景工作，Session 越多，總共讀檔和跑 `ps` 的次數越多。輕量掃描不能順便清理殘留的狀態回報以外的東西，也不能跑 git、gh。
- 按鈕的計數最多晚約 15 秒，監看視窗的計數最多晚約 3 秒，兩者短時間內可能不一致。
- 打開監看視窗後改用原本的 3 秒掃描，輕量掃描停止；監看視窗關掉後再恢復。
- 輕量掃描失敗時，按鈕不顯示計數，不能顯示 0（見 UX 審查：掃描失敗不能變成「沒有在等你」）。
