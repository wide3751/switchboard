# CLI Session 也能打開監看視窗

CLI Session（在終端機裡執行的 `claude`，含 VS Code 整合終端機）也可以打開監看視窗，取代 [0003](0003-single-desktop-board.md) 裡「CLI Session 看不到 mod 的任何畫面」的做法。使用者在終端機工作時也想看清單，不想為了看狀態切回 Desktop。mod 的 Pane 在終端機也能顯示，而且清單的畫法兩邊共用，所以不需要另外做一套。

為了不打擾原本只想用終端機的使用者，CLI 有自己的開關「所有 CLI Session 都顯示」，預設關閉，和 Desktop 的「所有 Desktop Session 都顯示」分開控制。監看視窗關著時，CLI 和 Desktop 一樣在輸入框上方放一個「▦ 打開監看視窗」按鈕。密度、欄位、語言等設定兩邊完全共用。

## Considered Options

- **CLI 跟著 Desktop 的開關自動打開**：沒有 Desktop 那樣的側邊欄，自動打開會擠壓對話紀錄，不適合當預設。
- **CLI 只在手動輸入指令時打開，沒有開關**：想常駐看清單的使用者每個 Session 都要自己開一次。
- **CLI 只顯示等你計數，不顯示清單**：改動小，但看到數字之後還是得回 Desktop 才知道是哪一個。
- **CLI 的密度和欄位另有一套設定**：可以讓終端機比較精簡，但兩套設定比較難理解；嫌太長可以自己調成精簡。

## Consequences

- 開關打開、但終端機太窄時，引擎不會畫出 mod 自動打開的 Pane。這時當作還沒打開，照樣顯示「▦ 打開監看視窗」按鈕；使用者按下去就算手動打開，不管寬度都會畫出來。
- 從 CLI 的監看視窗點 Desktop Session 照樣能跳轉；點 CLI Session 仍然只顯示資料夾路徑，跳轉到終端機分頁留給 ticket 06／07。
- VS Code 擴充套件的圖形介面不算 CLI Session，仍然不顯示監看視窗。
- 每個開著監看視窗的 CLI Session 也會各自每 3 秒掃描一次。監看視窗打開了但還沒畫出來時，仍會每 3 秒檢查它有沒有畫出來（不掃描），因為終端機變寬時引擎不會通知 mod。
- Desktop 有一個「焦點移到卡片標題就跳轉」的處理，只對 Desktop 生效。引擎的焦點事件不帶介面資訊，所以判斷的是 Session 有沒有 Desktop 介面：同時有 Desktop 和終端機介面的 Session，在終端機用鍵盤移動焦點時仍會跳轉。
- 監看視窗不是 mod 自己關掉、卻不見了，也算使用者手動關掉，那個 Session 就不再自動打開。所以別的 plugin 關掉它，效果也一樣。
- 一律顯示的按鈕代表：開關關著時，每個 CLI Session 的輸入框上方都會多一行。
