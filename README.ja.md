# switchboard：Claude Code のセッション監視ウィンドウ（Claude Code mod）

**Claude Code mods** で作られた **Claude Code プラグイン**です。Claude Code のセッションをいくつも開いているとき、ローカルのすべてのセッションを 1 つの **監視ウィンドウ** にまとめ、どれが作業中で、どれが待機中で、どれが**あなたの対応を待っているか**をひと目で分かるようにします。クリック 1 回でそのセッションへ移動して対応できます。

Claude Desktop の Code タブのセッションも、iTerm、Terminal.app、VS Code のターミナルで動く `claude` も、同じ一覧に並びます。Desktop とターミナルを同等にサポートしており、どちらか一方だけでもすべての機能を使えます。

</p>

<p align="center"><sub>イメージ図：対応が必要なセッションが 2 つ（承認待ちと回答待ち。それぞれ番号付きの「対応する」ボタン）、作業中が 2 つ、待機中が 1 つ。いちばん下はアカウント使用量。</sub></p>

電話交換手がどの回線のランプが点いているかを見るように、switchboard は各セッションに自分の状態を報告させ、あなたを待っているものを一番上に並べます：

| 状態 | 意味 | 例 |
|---|---|---|
| **▲ 対応が必要** | あなたが見ないと先に進まない | `npm install` の権限確認で停止、選択式の質問、Desktop のターン終了時の質問ボックス、API エラーで止まったターン |
| **◉ 作業中** | Claude がターンを実行中 | 思考、ツール呼び出し、サブエージェントの実行。ターンは終わったがバックグラウンドタスク（バックグラウンドのサブエージェントや Bash）がまだ動いている |
| **○ 待機中** | ターンが終わり、何もブロックされていない | 完了して次の指示待ち、自分で中断したターン |
| **終了** | セッションが閉じられた、またはプロセスが終了した | すぐに一覧から消える |

対応が必要は明確なシグナルにだけ反応するので、点灯したときは本当にあなたを待っています。Claude が普通のテキストで質問した場合は待機中になり、その行の最後の返信のプレビューで気づけます。

## クイックスタート

```bash
claude plugin marketplace add wide3751/switchboard
claude plugin install switchboard@switchboard
```

続けて、Claude Code を使う場所に合わせてどちらかの手順に進みます（両方でもかまいません）：

**Desktop**：Claude Desktop を再起動し、Code タブのセッションをどれか開きます。右側に監視ウィンドウが自動で表示され、以降はすべての Desktop セッションで自動的に開きます。表示されない場合は `/switchboard:open` と入力してください。

**ターミナル**：`claude` を再起動すると、入力欄の上に **▦ 監視ウィンドウを開く** ボタンが表示されます。クリックするか `/switchboard:open` と入力すると開きます。毎回自動で開きたい場合は、監視ウィンドウの **設定 ▸** › 一般で、「監視ウィンドウを自動で開く」の **CLI セッション** にチェックを入れます（ターミナルの幅が 144 桁以上必要です）。

インストール前から開いていたセッションも一覧には表示されますが、基本的な状態だけです。詳細を表示するには、それらのセッションを再起動してください。

次の文を Claude Code などのコーディングエージェントに貼り付けて、インストールを任せることもできます：

> Install switchboard by following https://github.com/wide3751/switchboard/blob/main/README.md

## 使い方

| コマンド | 説明 |
|---|---|
| `/switchboard:open` | このセッションで監視ウィンドウを開きます。Desktop でもターミナルでも使えます |

<p align="center"><sub>イメージ図：80 桁のターミナルで、入力欄の上に表示された監視ウィンドウ。内容は Desktop と同じです。</sub></p>

**監視ウィンドウの内容：**

- **ヘッダー**：あなたを待っているセッションがあるときは `▲ 2 件が対応待ち`、次の行に内訳と最長の待ち時間（例：`承認 1 · 回答 1 · 最長 3m`）。ないときは `✓ 対応が必要な項目はありません`。
- **セクション**：対応が必要 → 作業中 → 待機中。対応が必要は待っている時間が長い順で、最長のものが一番上です。待機中は見出しをクリックすると折りたためます。
- **カード**：1 行目は状態とタイトル。2 行目には一番大事なことを 1 つだけ表示します（実行しようとしているコマンド、質問と選択肢、進捗、または待機中の最後の返信など）。最後の行は場所、ブランチ、変更行数、`ctx 31%`、PR などの項目です。
- **対応する**：対応が必要なカードの右下に **1 対応する →** があります。クリックするか、監視ウィンドウにフォーカスがあるときに `1`–`9` を押すと、そのセッションへ移動します。
- **タイトルをクリック**：そのセッションへ移動します。Desktop セッションは Claude Desktop の該当セッションへ、iTerm・Terminal.app は該当するタブへ切り替わります。
- **時間と `▸` をクリック**（例：`3m ▸`）：カードを展開し、ブランチと比較の基準、コンテキストの使用量バー、コネクタ、フルパス、バックグラウンドタスクを表示します。
- **アカウント使用量**：サブスクリプションでは 5 時間と週ごとのレート制限、API 課金では合計コストを表示します。使用量が 95% に達すると、ヘッダーの下に移って知らせます。
- **監視ウィンドウが閉じているとき**：入力欄の上のボタンに対応待ちの件数が付き（例：**▲2 件が対応待ち · ▦ 開く**）、クリックすると開きます。

</p>

<p align="center"><sub>イメージ図：左上はエラーで停止（赤い太枠）、右は待っているものがなく 1 枚のカードを展開した状態、左下は状態を確認できないときの警告カード。</sub></p>

**ターミナルのキー操作**（マウスのクリックを伝えないターミナルで使います）：

| キー | 動作 |
|---|---|
| `ctrl+x tab` | 入力欄から監視ウィンドウに移動 |
| `tab`／`shift+tab` | ボタンとタイトルの間を移動 |
| `enter` | 選択中のボタンやタイトルを押す |
| `1`–`9` | その番号の **対応する →** を押す |
| `esc` | 監視ウィンドウを開いたまま入力欄に戻る |
| `ctrl+x x` | 監視ウィンドウを閉じる |

**設定**（ヘッダー右端の **設定 ▸** を押します。すべてのセッションで共有）：

- **カードの内容**：対応が必要、作業中、待機中のそれぞれに表示する項目を選ぶか、コンパクト、標準、詳細から選びます
- **監視ウィンドウを自動で開く**：Desktop セッションはデフォルトでオン、CLI セッションはデフォルトでオフ。別々に設定できます
- **言語**：自動、English、日本語、한국어、简体中文、繁體中文
- **課金**：自動、サブスク（レート制限を表示）、API（コストを表示）

**通知**：switchboard 自身は通知を送らず、Claude Code と Claude Desktop 自身の通知に任せます。ターミナルでは `claude` で `/config` を入力して通知方法を設定し、Desktop では「システム設定 › 通知」で Claude の通知を許可します。

すべての項目、記号、並び順のルール、ターミナルごとの詳細は [詳しい使い方](docs/guide/usage.ja.md) を参照してください。

## プライバシーとセキュリティ

switchboard は**すべて Mac 上で動作し**、独自のサービスにデータを送信することはありません。

**読むもの**

- Claude Code 自身のセッション記録（`~/.claude/sessions/*.json`）。どのセッションがあるかを知るために使います
- 自分で書き出したステータスレポート
- **他のセッションの会話ログは読みません**

**書き込むもの**

- 各セッションのステータスレポート。`~/.claude/switchboard/reports/` に平文の JSON として保存され、いつでも開いて中身を確認できます
- 内容はタイトル（最初のプロンプトの先頭約 40 文字）、モデル、ブランチ、現在の操作、承認リクエストの概要、最後の返信の短い抜粋、コンテキストの使用量など
- 書き込む前に、機密らしき部分（`Bearer …`、`token=…`、`sk-…`、`ghp_…` など）を `•••` に置き換えます。ベストエフォートなので、すべてを検出できるわけではありません
- セッションが終了すると、古くなったレポートは自動で削除されます

**実行するコマンド**

- `ps`：どのセッションが生きているかを確認
- `git`：セッションのフォルダでブランチと変更を読み取る
- `gh pr view`：プルリクエストを確認。あなた自身の `gh` ログインを使います。ネットワークに接続するのはこのコマンドだけで、`gh` がなければ接続しません
- `open`、`osascript`：クリックしたときだけ実行し、該当するセッションやタブへの切り替え、ブラウザでのプルリクエストの表示に使います

古くなった自分のレポートを削除する以外に、switchboard があなたのファイルやリポジトリを変更することはありません。コードはすべてオープンソース（MIT）なので、自分で確認できます。項目ごとの説明は [プライバシーとデータ](docs/guide/privacy.ja.md) を参照してください。

## 動作要件

- macOS
- 次のどちらかの Claude Code（両方でもかまいません）：
  - [Claude Desktop](https://claude.ai/download) アプリの Code タブ
  - ターミナルの `claude`（iTerm、Terminal.app、VS Code の統合ターミナルなど）
- mods に対応した Claude Code：**v2.1.299** で開発・テストしています。Desktop では Code タブで `/status`、ターミナルでは `claude --version` でバージョンを確認できます。Desktop に同梱の Claude Code はターミナルのものとバージョンが違うことがあるので、それぞれ確認してください
- 任意：`git`（ブランチと変更の情報）、ログイン済みの [`gh`](https://cli.github.com/)（プルリクエストの情報）

## 更新・無効化・削除

**更新する**（インストール済みのプラグインに `install` をもう一度実行してもアップグレードされません）：

```bash
claude plugin marketplace update switchboard
claude plugin update switchboard@switchboard
```

**一時的に無効にする**（インストールしたまま、あとで `enable` で有効に戻せます）：

```bash
claude plugin disable switchboard@switchboard
```

**完全に削除する**：

```bash
claude plugin uninstall switchboard@switchboard
claude plugin marketplace remove switchboard
rm -rf ~/.claude/switchboard
```

- 最後の行でステータスレポートを削除します。プラグインを削除しても自動では消えません。`CLAUDE_CONFIG_DIR` を設定している場合は `$CLAUDE_CONFIG_DIR/switchboard` を削除してください
- 更新、無効化、削除のどれも、Claude Desktop と開いている `claude` を再起動すると反映されます

## 制限事項

- **macOS のみ**：Linux では開けますが移動できません。Windows には `ps` がないため、セッションの状態を確認できません。
- **CLI セッションへの移動は iTerm と Terminal.app のみ**：ほかのターミナルではセッションのフォルダが表示されるだけです。
- **ターミナルが狭いと自動では開きません**：幅が 144 桁以上必要です。狭いときも、入力欄の上のボタンを押せば幅に関係なく開きます。
- **3 秒ごとに更新**：変化は即時ではなく数秒以内に反映されます。
- **インストール前から開いていたセッションは基本状態のみ**：エラー停止、承認リクエストの概要、最後の返信は表示されません。再起動すれば表示されます。
- **ローカルのセッションのみ**：サブエージェントとクラウドセッションは表示しません。

## トラブルシューティング

セッションの状態を確認できないとき、監視ウィンドウの警告カードの「トラブルシューティング ↗」はここにつながります。

| 症状 | 対処 |
|---|---|
| 行に `switchboard 未読み込み、基本状態のみ` と表示される | そのセッションはインストール前から開いていました。再起動してください |
| `/switchboard:open` が hooks が読み込まれていないと返す | お使いの Claude Code が mods に対応しているか確認し、このセッションを再起動します。それでも解決しなければ、`claude --debug` で起動し、ログで `hooks module switchboard` を探します |
| `⚠ 現在セッションの状態を確認できません` と出て、セッションの記録が 1 件もないと表示される | Claude Code が古いか、`CLAUDE_CONFIG_DIR` が Claude Code の実際のフォルダ以外を指しています |
| `⚠ 現在セッションの状態を確認できません` の下に赤字が出る | 赤字は元のエラーメッセージです。3 秒ごとに自動で再試行するので、一時的なエラーなら自然に消えます。消えない場合は `claude --debug` で起動して確認します |
| `⚠ 現在セッションの状態を確認できません` と出て、フォルダを読み込めないと表示される | そのフォルダが存在し、読み取り権限があるか確認してください |
| PR が表示されない | `gh` をインストールして `gh auth login` を実行。フォルダが GitHub リポジトリである必要があります |
| CLI セッションをクリックしても移動できない | 移動できるのは iTerm と Terminal.app だけです。この 2 つでも移動できない場合は、「システム設定 › プライバシーとセキュリティ › オートメーション」で操作を許可してください |

そのほかのケースは [トラブルシューティングの詳細](docs/guide/troubleshooting.ja.md) を参照してください。
